### Autopilot-full

Run independently acceptable changes through their full authorized lifecycle. Full autonomy is bounded by the user's actual scope and host permissions.

1. Map the queue to existing Plans and Release scope. Keep tasks, dependency contracts, shared-file ownership and handoff in native metadata.
2. Give each useful worker the original goal, Plan, REQ/AC, exclusive writes, checks, publication boundary and report contract. Choose current host delegation and .ai/pstack/config.json role models. There is no required Cursor cloud agent or fifteen-minute PR deadline.
3. Require a verifiable unit before the next one. Record reasons and decisions in the Plan through show-me-your-work. Track children through actual host status and Plan handoff; do not create decisions.tsv or children.tsv.
4. Review final files and evidence at their real version. Triage CI/reviewer findings skeptically and fix accepted defects in the same outcome's Plan. Run native Plan checks; independent review is proportional to risk.
5. Prepare PRs and merges only when authorized, using opening-a-pr, babysit and shipping. Record actual branch/head and dependency; do not unconditionally force-push or merge because the playbook says autopilot.
6. A requested recurring audit uses the actual host automation tool, not a fabricated /loop command. At a tick read the current checked-out method and native state, report only meaningful changes, and reuse unchanged passing checks.
7. Reconcile every assigned scope. Run the Release final check after included Plans are done. Report completed outcomes, evidence, versions and remaining conditions.
