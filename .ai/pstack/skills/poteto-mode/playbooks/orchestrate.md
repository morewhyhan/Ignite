### Orchestrate

Own a standing program through clear briefs, bounded delegation, continuous integration and auditable decisions. A task one agent can finish uses Autonomous run or figure-it-out instead. Keep these methods: size units by an independently acceptable outcome, pilot novel work once, refill ready work as workers finish, relay upstream context, and reconcile every child.

#### Native state and roles

Use Feature for requirements, Plan tasks for work, dependency_contracts/shared_files/handoff for collaboration, Plan judgments and blocker/open_questions for decisions, native evidence for checks, and Release scope for combined delivery. Generate status using pnpm ignite status --write. Do not initialize preferences.md, units.tsv, ledger.tsv, gates.md or another status register.

The coordinator frames and reviews results; workers own disjoint writes; a verifier adds an independent view when risk warrants it. Do not force a cloud VM, Graphite, a different model family or a durable sub-coordinator. Role selection reads .ai/pstack/config.json and actual host capabilities. Source orch tools remain optional standalone resources, not the native execution entry or the authority for Ignite completion.

#### Brief

Every assignment carries GOAL, SCOPE including forbidden paths, CONTEXT with upstream findings, ACCEPTANCE using actual REQ/AC, VERIFY with supported commands, STOP CONDITION, and REPORT with version, results and limitations. Reference AGENTS.md and the applicable native Plan instead of copying another standing-orders file. Collapse this to a short paragraph for a small unit.

#### Execution

1. Define the real completion predicate and authorized boundary in the existing Plan/Release. Do not silently add pushes, PR merges or deployment to a local outcome.
2. Find ready tasks from native dependencies. Mark work through pnpm ignite task set-status <ID> <task> <todo|doing|done>; refresh derived progress with pnpm ignite plan refresh <ID>.
3. Pilot a novel unit through its actual checks. A cheap repeated edit uses the first normal unit as the pilot; do not add a special verification pipeline.
4. Spawn useful independent scopes with exclusive files/worktrees. Refill on completion; record consequential handoff facts in the existing Plan. A completion notification is a review event, not proof of acceptance.
5. At a drain point review the actual diff and receipts, update task states and dependencies, and assign newly ready work. Preserve completed evidence rather than rerunning unchanged inputs.
6. Integrate continuously at safe boundaries. Give each shared branch one writer; record the actual base/head and dependency in the Plan. Git/forge reads establish the stack, not assumed Graphite metadata. Do not rebase or publish beyond authorization.
7. Run native Plan checks and, once all included Plans are complete, the Release final check. CI green or a worker verdict cannot replace native evidence. New versions follow native invalidation/reuse rules, not patch-id alone.
8. Close by reconciling each delegated scope and the original goals. Report actual accepted results, blocked/deferred work, versions and evidence. Keep human questions in existing open_questions/blocker; continue independent work without inventing a second gate page.

#### Failure and recovery

Probe actual host agent/process status and file/commit progress. A transcript timestamp alone is not liveness. Bound retries and reduce scope for repeated resource failures. Late reports must be compared to current files and evidence before integration. Recover from native Plan tasks, git state and evidence after restart; do not presume cloud agents survived. Schedule background follow-ups only through an available host facility and only when requested.
