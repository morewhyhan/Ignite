### Worktree cleanup

Reclaim space while preserving the user's work. A merged branch, old commit, or untracked file does not prove a checkout is disposable.

1. Inventory first. From the project root run `bash .ai/pstack/skills/poteto-mode/scripts/worktree-audit.sh`. It reads full paths from Git, supports spaces, reports tracked and untracked changes separately, and uses cached refs. It does not fetch, scan private transcripts, install packages or delete files. Use `--fetch` only when refreshing remote refs is within the current task. Commit age is not last usage; ignored files and running processes need separate review.
2. Establish ownership and active usage. For Codex, inspect task artifacts and the relevant active or pinned chats using host tools. Do not infer inactivity from age or a merged PR. Do not scan unrelated private conversations. A clean status does not cover ignored databases, build artifacts or other local data.
3. For managed Codex worktrees, prefer the host `archive_worktree` operation with the exact identity from `list_artifacts`. This preserves a recoverable snapshot of local changes, unpushed commits and non-ignored untracked files. Preserve needed ignored files separately first. Primary, pinned, shared, embedded-repository or initialized-submodule checkouts may refuse archival; retain them and report the reason. Do not bypass host safeguards using Git or directory deletion.
4. For an ordinary Git worktree covered by the user's cleanup request, verify its resolved absolute path and intended directory, ownership, active processes, tracked changes, untracked files and needed ignored data. Preserve necessary work first. Once the candidate is confirmed inactive and its content preserved, use normal `git worktree remove <absolute-path>` without force. If Git refuses, investigate and retain the directory; do not follow with recursive deletion. Removing a branch or unrecoverable data requires explicit authorization for that loss.
5. On Windows, use native PowerShell file operations with `-LiteralPath` for any separately authorized file preservation or removal. Resolve and check the absolute target stays within the explicitly intended directory before recursive operations; do not mix PowerShell path enumeration with shell-built deletion commands.
6. Confirm the worktree inventory and actual reclaimed space afterward. Report what was archived or removed, how work was preserved, and which candidates remain because they are active, have unpreserved data or are blocked by the host. Do not automatically clear simulators, application state or package caches as an extra cleanup step.

This playbook carries the upstream inventory-and-preservation method into Ignite. Its report is not permission to delete and is not Plan/Release completion evidence.
