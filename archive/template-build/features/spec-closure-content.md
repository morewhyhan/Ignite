# Ignite 功能规格：计划内容门禁

## 背景与目标

计划模板有章节，但检查只比对标题是否存在。空的"主要矛盾"、抄模板提示语的"决策原则"都能通过，读者无法据此判断方案是否成立。本规格要求声明内容契约的计划，其分析章节必须有实质内容，且不得残留模板提示语。

## 用户行为与边界

| 使用者与条件 | 动作或输入 | 观察结果                   | 重要权限或失败边界                   | 已有依据                 |
| ------------ | ---------- | -------------------------- | ------------------------------------ | ------------------------ |
| 维护者       | 提交计划   | 缺章节、空章节或模板语被拒 | 只有声明 content_contract 的计划受限 | 用户 2026-11-06 收尾指令 |

## 模块边界

- 规格位置：`docs/features/spec-closure-content.md`
- 校验：`scripts/ignite/content-contract.mjs`，由 `validatePlan` 调用
- 断言：`tests/contracts/spec-closure-content.test.ts`

## 业务规则

- R1（REQ-SPEC-008）：声明 `content_contract: 1` 的计划必须包含来源规格、目标映射、主要矛盾、次要矛盾、决策原则、方案比较、约束绑定矩阵、回退八个章节，且每节有最小实质行数，不得包含模板提示语。

## 权限、错误与缓存

- 数据归属：不涉及业务数据。
- 非法输入：缺章节、实质行数不足、命中模板提示语，均视为失败并指出章节。

## 数据变化与回退

- 既有数据影响：只对新契约计划生效，历史计划不追溯。
- 回退：撤销提交即可恢复。

## 原型与交互

- 不适用。

## 非目标

- 不追溯改造 P0–P3 已完成计划。
- 不做语义质量评分。

## 验收标准

- AC-SPEC-008（REQ-SPEC-008）：Given 计划声明内容契约但缺少章节、章节为空或含模板提示语 When 运行内容校验 Then 失败并指出章节；模板与合规计划通过。
