# GOAL 研究：本项目

> 这份文件放研究过程，不放需求本身。需求在 [GOAL.md](./GOAL.md)；写法见 [GOAL 规格](GOAL-spec.md)。
> 每次读 GOAL 时，两份一起读：先看研究怎么来的，再看金字塔要什么。

## 一、目标分析

目标：让一个人从一个想法开始，直接用一套能跑、能验、能继续改的代码做出自己的应用。

先把词说清楚。

**人**：要自己做产品的人，不一定是程序员。他可能只会说“我想做一个记任务的东西”。

**想法**：一句模糊的诉求，还不是需求。要先变成目标、领域、规则、验收。

**能跑、能验、能继续改**：跑得起来；每条规则都有测试；后面加需求时不用推倒重来。

**不做什么**：不做低代码平台，不做团队协作，不做多租户。

## 二、场景分析

```
新用户
  成功：打开首页 → 注册 → 进入工作台
  失败：邮箱已占用或密码不合规 → 提示 → 留在注册页
  异常：注册中途关掉页面 → 下次重新注册

老用户
  成功：打开首页 → 登录 → 恢复会话 → 进入工作台
  失败：凭证错误 → 提示 → 留在登录页
  异常：会话过期 → 访问受保护页 → 被带回登录页

登出
  成功：点登出 → 会话失效 → 回首页
  异常：登出后按后退键 → 仍停在首页

任务
  成功：进入任务页 → 新建 → 出现在列表 → 完成 → 删除
  失败：标题为空或超长 → 提示 → 不保存
  异常：打开别人的任务 → 按不存在处理
```

## 三、事件风暴

```
认证：注册成功、注册失败、登录成功、登录失败、会话建立、登出成功、会话失效、访问被拒
任务：任务创建、任务更新、任务完成、任务删除、越权访问被拒、列表返回
```

## 四、命令风暴

```
提交注册（未登录用户；用户名、邮箱、密码；已登录或邮箱占用不能注册）
提交登录（未登录用户；邮箱、密码；凭证错误不能登录）
点击登出（已登录用户；无输入；未登录不能登出）
打开受保护页面（任意访问者；页面地址；没有有效会话不能访问）
创建任务（已登录用户；标题；未登录或标题非法不能创建）
编辑任务（任务所有者；任务 ID、标题；非所有者不能编辑）
完成任务（任务所有者；任务 ID；非所有者不能完成）
删除任务（任务所有者；任务 ID；非所有者不能删除）
获取任务列表（已登录用户；无；未登录不能获取）
```

## 五、识别模型

```
实体：用户、会话、任务
值对象：邮箱、密码哈希、标题
聚合：用户（根）+ 会话；任务（根）
```

## 六、识别上下文

```
认证：账号与会话是同一条事件链，合并；权限分级没有多角色需求，不做
任务：任务有自己的实体与生命周期，和身份是两套规则，独立
外壳：没有业务事件，只做路由与布局，不算领域
```

## 七、统一语言

```
用户 = 有账号的人
会话 = 一次登录的凭证
任务 = 一条待办，有标题、状态、归属
所有者 = 任务所属的账号（任务领域不用“用户”这个词）
```
