# Ignite 视觉设计系统

本文档固定当前 Ignite UI 的可复用视觉规则，供新增页面和组件参考。颜色、圆角、动画和基础间距的最终实现仍以 `src/app/globals.css` 与 `src/components/ui/` 为准。

## 视觉方向

- 默认主题使用中性蓝灰色底和高对比度蓝色重点，强调清楚、克制、便于长时间使用。
- 页面背景与卡片保持轻微明度差异；边框用于划分真实内容区域，不靠大面积阴影或渐变制造层级。
- 交互反馈只对需要反馈的控件添加短时过渡；禁止对所有元素设置全局 transition。
- 主题提供蓝、青绿、深紫、砖红、琥珀、石墨灰六种配色，旧版 `color-scheme` 本地偏好会映射到最接近的新主题。
- 深色主题通过同一组 CSS 变量切换，不在业务组件内硬编码颜色。

## 颜色令牌

| 令牌                  | 当前值    | 用途                   |
| --------------------- | --------- | ---------------------- |
| `--scheme-primary`    | `#315ee8` | 主按钮、选中态、焦点环 |
| `--scheme-secondary`  | `#e8edff` | 次要强调背景           |
| `--scheme-background` | `#f6f8fc` | 页面背景               |
| `--scheme-foreground` | `#172235` | 正文和标题             |
| `--scheme-muted`      | `#64748b` | 辅助文字               |
| `--scheme-border`     | `#e2e8f0` | 边框、输入框和分隔线   |
| `--scheme-card`       | `#ffffff` | 卡片和弹层             |
| `--destructive`       | `#ff6b6b` | 删除和危险操作         |

新增 UI 优先使用 Tailwind 语义令牌，不要直接写颜色值。

## 组件约束

- 基础组件统一复用 `src/components/ui/`。
- 页面标题通常使用 30–40px 字号，正文 14–16px；避免首页超大标题与大块留白挤压实际信息。
- 工作台内容区必须避开固定侧栏；移动端导航使用明确的按钮名称，触屏操作不能依赖 hover 才显示。
- 主题选项收纳于命名清楚、可键盘操作的菜单，不在主页面散布无标签色点。
- 卡片优先使用中等圆角和细边框；按钮动效应短且不改变布局，不使用普遍性的漂浮、缩放和重阴影。
- 业务组件放在对应的 `src/modules/<module>/components/`。
- 表单、弹窗、表格、提示和加载状态优先使用现有 UI 组件。
- 页面必须处理 `loading`、`error`、`empty` 和正常数据状态。
- 交互状态优先使用 CSS 变量和现有动画令牌，不在单个页面创建重复主题。
- 首页访客路径先用“使用情境 → 用户任务 → 实际结果”说明价值：从可运行底座开始，交付可体验、可验证的版本，并能接续迭代。文档区以文件目录展示 `AGENTS.md`、`.ai/` 和 `docs/` 下各类资料，并解释统一规则、职责分工和后续接续的作用；Plan 记录本轮过程，Design 保存当前事实。
- 首页首尾提供两个不同入口：“开始使用”前往项目 GitHub 仓库；“预览应用”在已登录时进入工作台，未登录时打开注册面板，可切换为登录。保留真实邮箱密码认证，不提供自动登录或独立 Demo。品牌宣言之后的深色底栏简述模板定位及快速启动、快速验证、持续迭代的理念。
- 登录/注册共用一个认证面板：桌面端左侧简述 Ignite 的开发方式，右侧呈现表单；窄屏收起说明栏，优先保证表单完整、可滚动且操作清楚。表单使用简洁边框和主题色，不使用渐变按钮或图标堆叠。

## 响应式与布局

- 使用 Tailwind 响应式断点。
- `.container` 的水平内边距为 `2rem`，最大宽度随断点从 `640px` 到 `1400px` 变化；窄屏页面壳优先使用 `1.25rem` 内边距。
- Dashboard 页面由 `src/components/layout/dashboard-layout.tsx` 统一提供布局。
- 模板基线至少覆盖 1440px 桌面、768px 平板、390px 与 360px 手机宽度；页面不得产生横向溢出，认证和编辑弹窗必须限制在视口内并允许内容滚动。
- 当前响应式用户路径由 `tests/e2e/responsive.spec.ts` 验收；新页面应在同一主要流程上补充窄视口行为检查，而不只检查 CSS 类名。

## 变更规则

修改视觉基线时，同时更新本文档、`src/app/globals.css` 和受影响的 UI 组件，并通过 Playwright E2E 或浏览器手动验证关键交互。响应式主题与首页基线由 `tests/e2e/visual-baseline.spec.ts` 覆盖。
