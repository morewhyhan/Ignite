# 需求规格

这里维护产品或业务需求。模块规格说明用户需要什么；本页负责需求怎样编写、修改和验收，模板提供填写位置。

## 需求写到能判断行为

从用户原始结果倒推必要条件，写清谁在什么条件下操作、输入如何处理、可观察结果及重要边界。合格规格应让不同实现者对同一行为得出相同的正确或错误判断，不替实现指定每个函数和工具调用。

沿本功能相关的输入、处理、保存、读取和呈现核对权限、依赖与失败状态；只列适用环节。已读规格、Design、代码和运行结果作为事实依据，未确认原因保留为推测。只调查会改变产品行为、范围或验收的未知，证据显示影响扩散时再扩大阅读。

“支持保存”不足以区分临时显示和持久化。若用户已经确定“当前用户保存后刷新仍能看到自己的内容，失败保留输入并显示错误”，这才足以验收。示例边界不能自动成为所有项目的默认承诺。简单文案修改引用已有行为即可，不重新论证数据库或整个系统。

产品结果、权限、数据含义或失败行为有实质分歧时，先查既有决定和授权；仍未确定的交给人选择，继续不依赖它的工作。普通可回退的实现选择由执行者处理。

## 规格内容与尺度

每份规格按功能适用性包含：

- 背景、用户目标和来源；
- 模块边界、字段与校验、数据归属；
- 正交业务规则、权限与重要失败行为；
- 页面或原型依据、loading/error/empty/pending/success 等适用状态；
- 可观察验收标准、非目标和存量兼容要求；
- 涉及数据变化时的迁移、旧数据验证及回退；破坏性变化引用授权。

进入实现前不能保留占位规则、验收或关键产品决定。适用内容已经明确时引用原规格，不为凑栏目创造新承诺；没有外部原型时可说明以当前设计系统为依据。

## AC 的编写与覆盖

业务规则使用稳定 `REQ-*`，AC 使用稳定 `AC-*` 并列出覆盖的 REQ。AC 的 Given/When/Then 应能独立判断行为是否成立；保存与刷新共同构成一个结果时可以是一条旅程，权限等独立边界另行断言。边界和失败按真实风险选择，不按函数数或测试数判断充分性。

从原始承诺定义正确结果，再建立测试；不能只从实现后的代码反推要验收什么。行为层级与断言质量由 [测试标准](../standards/testing.md) 定义；测试关联只证明已列目标，遗漏审查在 [Plan 原始目标核对](../plans/README.md#输入与原始目标核对) 中记录，组合范围由 [Release](../plans/releases/README.md) 维护。

## 修改与维护

需求新增或存量变化在对应 Plan 留下来源和范围，更新受影响的规则与 AC；本轮修复沿用原 Plan。新承诺先更新规格及验收，再改实现；取消或排除原承诺须有人的决定，缺账号、未实现和外部条件不足不能静默删除。

需求保存产品意图，Design 保存当前事实。两者出现差异时在本轮修正，或由 Plan 明确记录尚未解决的影响。原规则仍适用时复用；已交付结果的下一次改动建立存量 Plan，保留历史证据。

需求尺度参考 [NASA 需求编写指南](https://www.nasa.gov/reference/appendix-c-how-to-write-a-good-requirement/)。这是本项目采用的工程方法，不能据此证明任何模型已准确理解需求。

## 固定维护方法

涉及本类文档时，先读取以下必需方法：[how](../../.ai/pstack/skills/how/SKILL.md)、[principle-experience-first](../../.ai/pstack/skills/principle-experience-first/SKILL.md)。必须按下面的顺序处理，不能由 AI 自行省略；未触及本类文档时不强制执行。

1. 先还原用户已确定的目标、实际使用过程和约束，区分新增模块与存量改动；已有 Feature 能承载时在原处更新。
2. 把用户行为写成 REQ 与可观察的 AC，说明采用边界、失败情况、必要验收层级及真实检查路径；不由 AI 猜测尚未决定的产品取舍。
3. 对照原始目标逐条检查遗漏，再交给对应 Plan。未明确的关键决定保留为问题，不用空的问题列表冒充完整。

历史理由影响本次取舍时读取 [why](../../.ai/pstack/skills/why/SKILL.md)；改变架构边界时读取 [architect](../../.ai/pstack/skills/architect/SKILL.md)；只有真实使用问题需要实验区分时才采用 [prototype](../../.ai/pstack/skills/poteto-mode/playbooks/prototype.md)。普通文案修改不强制原型或额外代理。产出仍在 Feature，执行与决策过程写入对应 Plan。
