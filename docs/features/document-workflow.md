# 文档维护与精细执行

## 背景与目标

让采用 Ignite 的 AI 从真实需求进入稳定文档基线，按可验收任务和固定独立审查维护体系。承接本会话已确定的 AGE 取舍与用户对 Plan 精细度的要求。

## 业务规则

- R1（REQ-DOCFLOW-001）：新脚手架提供任务结果、局部写入范围、依赖和负责人，保持单一任务状态；新契约要求这些字段真实完整。
- R2（REQ-DOCFLOW-002）：官方准备、任务推进和接续拒绝任务没有可观察结果、范围越界、未知或循环依赖；依赖未完成不得启动下游任务。历史未启用新契约保留原语义。
- R3（REQ-DOCFLOW-003）：新契约在正式开工与交付要求对应对象的独立审查记录；原目标、任务语义或受审实现变化使记录失效，纯状态回填不失效。审查记录保存真实来源、执行者和审查者，不能同一人自评；工具只能核对声明，不证明任意宿主身份。
- R4（REQ-DOCFLOW-004）：固定方法写在现有职责入口，两份审查正文维护在项目技能真源；克隆内可按名读取并由发现目录桥接。稳定业务、长原始材料和冲突分类有唯一职责，不引入平行适配文件或状态。

## 验收标准

- AC-DOCFLOW-001（REQ-DOCFLOW-001）：Given 新存量脚手架，When 起草计划，Then 生成可细化的任务结果、范围和依赖及审查契约，不用笼统标题替代交付结果。
- AC-DOCFLOW-002（REQ-DOCFLOW-002）：Given 新任务契约，When 任务无结果、越界、依赖未知或成环，Then 官方入口拒绝并指出任务；依赖完成前不能启动下游；旧 task_contract:1/2 未声明新契约时仍按旧语义准备与推进。
- AC-DOCFLOW-003（REQ-DOCFLOW-003）：Given 新审查契约，When 对象未审、审查者等于执行者、未解决发现或受审输入变化，Then 准备或完成入口保持未通过；有效非自查记录可用于对应阶段，状态回填不误判过期。
- AC-DOCFLOW-004（REQ-DOCFLOW-004）：Given 完整克隆，When 从技能读取与所属规则进入方法，Then 两份独立审查正文和引用在项目内闭合，发现入口只桥接；独立内容核对确认稳定事实、来源、冲突和技能职责仍由原文档承载。

- AC-DOCFLOW-005（REQ-DOCFLOW-003）：Given 旧 Git index 保留 CRLF 且后来启用文本属性，When 文件实际未改变，Then 当前与历史审查身份一致；真实编辑仍使身份变化，不通过忽略差异来放行。

## 模块边界

文档职责由所属 README 和专业标准维护，当前执行事实回写 docs/designs/execution.md；脚手架负责起草，scripts/ignite 负责契约和准入，项目技能只提供思考与审查方法。业务代码、数据访问及认证行为保持现有边界，审查记录不替代任何测试或权限判断。

## 采用边界

本轮是文档与本地工程工具重构，适用 unit 验收；无新增业务页面、持久化或第三方服务。真实模型是否始终遵守这些步骤仍需独立观察，不能由工具测试替代。原生子 Agent 可用于本次独立审查，不搬 AGE 引擎或宿主插件。

## 非目标

不改变 Tasks、认证、数据库和部署行为；不取消真实红灯和 Release 验收；不把所有技能要求为每次必读。

## 失败与回退

发现记录缺失、过期或与目标矛盾时回原 Plan 修复；不把缺口标为通过。历史记录未启用新契约继续按旧规则解释，回滚通过对应 Git 提交恢复工具与规则。
