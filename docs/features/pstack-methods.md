# Ignite 项目方法库

## 背景与目标

作为采用Ignite的开发者，我希望完整克隆项目后便携带pstack方法库，所用Agent能发现适用技能、读取同一真源，并遵守Ignite的目标、权限及工程规则。不要求先证明技能提速；不自动启用云服务、模型订阅、外部写入或定时任务。

这是存量工作台资产改动，无业务页面、API、数据库或用户数据迁移。方法正文和配套资源直接使用；工具发现文件只桥接，不维护第二套方法或规则。

## 业务规则

- R1（REQ-PSTACK-001）：项目携带Lauren Tan pstack快照的152个保留源文件，包含51个主技能、23个playbook、配套Agent/参考/资源和MIT许可；不包含上游12份问题报告机器人文件，来源清单记录保留和排除范围；来源及每个原始/本地文件哈希可追溯。
- R2（REQ-PSTACK-002）：Codex、Claude Code、Cursor、OpenCode的项目技能入口均包含名称、适用描述和真源链接；AGENTS及现有工具桥接登记统一目录，支持不具备技能发现目录的宿主按路径读取。克隆不依赖开发者的TEMP路径或全局技能安装。
- R3（REQ-PSTACK-003）：必要的项目文档位置、模型配置和工具调用要求直接写在使用它们的技能或流程中，不依赖独立适配文件。用户启用poteto-mode后由AI选择流程与技能，继承方法仍遵守项目规则与当前授权；模型默认继承、工具使用实际宿主能力。简单任务不默认多Agent/全面调查，模型实验不作为复用门槛。

实际执行步骤把决策、阶段、协作和验证指回原生 Plan/Feature/Design/证据，不初始化第二账本。新增技能正文在 `.ai/skills`，同步工具生成入口、目录和本地来源哈希，拒绝覆盖同名非生成技能。角色选择实际读取项目 `config.json`；辅助工具不隐式安装，工作区清理保留未提交资料。

## 模块边界

存量工作台改动；`.ai/pstack`为方法真源，两个必要目录为发现桥接，服务四种工具，不涉及业务模块、API、页面或数据库。

## 验收标准

- AC-PSTACK-001（REQ-PSTACK-001）：Given 项目完整克隆，When 从sources.json逐条定位本地文件，Then 文件数与来源相符，完整技能/工作流程资源可读，MIT版权保留，未经适配的二进制及脚本内容与上游哈希一致。
- AC-PSTACK-002（REQ-PSTACK-002）：Given 宿主加载项目，When 遍历51个继承技能在两个必要发现目录的102个入口，Then Cursor/OpenCode复用兼容目录，无冗余生成入口；元数据可解析，真源链接在克隆的项目目录内存在，正文只有入口指引；不含本机TEMP绝对路径。
- AC-PSTACK-003（REQ-PSTACK-003）：Given 读取继承方法，When 逐类核对固定模型、Cursor工具、全局配置、外部动作、工程步骤、可选自动化的映射，Then 继承Markdown与发现入口不要求额外读取适配文件，项目规则声明真源及使用方式；同步生成器在不含适配文件的项目中仍能生成直接指向正文的入口。此项是内容与文件检查，不是模型准确率或耗时评估。

## 采用与未验证范围

支持项目技能发现的宿主需加载/刷新项目技能目录；已有会话是否实时刷新由宿主决定。没有声称四个平台均已真实运行验证。MCP、模型切换等依赖只在采用项目明确启用时配置；克隆不会创建服务或授权。业务验收仍归现有Plan/Release规则。
