# 规格闭环：设计连接性

## 背景与目标

设计文档目前同时承载"当前系统是什么"和"打算改成什么"，读者无法分辨哪一段是已实现事实、哪一段是目标设计。
计划完成时也没有回写台账，导致计划标了 done 但设计没更新也无人发现。

本模块要做的：给每份设计文档加状态标记，并建立"计划 → 设计文档"的回写台账。

## 业务规则

- R1（REQ-SPEC-012）：每份设计文档必须在标题后声明自己是"当前事实"还是"目标设计"，取值只有这两种。
- R2（REQ-SPEC-013）：必须存在回写台账，列出每份设计文档由哪些计划维护。

## 验收标准

- AC-SPEC-012（REQ-SPEC-012）：Given docs/designs 下的设计文档 When 检查正文 Then 每份都含 `> 状态：当前事实` 或 `> 状态：目标设计` 之一。
- AC-SPEC-013（REQ-SPEC-013）：Given 回写台账文件 When 检查内容 Then 每份设计文档都在表格中被列名，且表格至少有一行计划归属。

## 模块边界

只新增检查与文档标记，不改动业务代码、路由与数据模型；设计文档的正文内容不在本模块重写。
