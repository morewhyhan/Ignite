# Ignite 功能规格：规格闭环账本

## 背景与目标

52 条差异账本记录了"谁负责"，但没有记录"做到了没有"。结果是账本把计划意图当成实施结果，读者无法据此判断还剩多少工作。本规格要求账本为每条记录实施结果，并让已完成条目指向真实计划；证据引用留到后续阶段。

## 用户行为与边界

| 使用者与条件 | 动作或输入     | 可观察结果                                  | 重要权限或失败边界         | 已有依据                 |
| ------------ | -------------- | ------------------------------------------- | -------------------------- | ------------------------ |
| 维护者       | 读取账本       | 每条都有实施结果（met / partial / missing） | 缺字段或取值非法时校验失败 | 用户 2026-11-06 收尾指令 |
| 维护者       | 把某条标为 met | 该条必须指向真实计划                        | 无计划却标 met 时校验失败  | 同上                     |

## 模块边界

- 规格位置：`docs/features/spec-closure-ledger.md`
- 账本：`docs/others/spec-closure/ledger.json`
- 校验与断言：`tests/contracts/spec-closure-ledger.test.ts`（读账本与真实计划集）

## 业务规则

- R1（REQ-SPEC-007）：账本每条必须包含 `result`，取值为 met、partial 或 missing；标为 met 的条目必须填写真实计划编号。

## 权限、错误与缓存

- 数据归属：不涉及业务数据，仅模板仓库内的治理记录。
- 非法输入：缺 `result`、取值不在枚举内、met 条目没有计划，均视为校验失败。

## 数据变化与回退

- 既有数据影响：账本条目增加一个字段，不删除历史。
- 回退：撤销提交即可恢复，字段为纯增量。

## 原型与交互

- 不适用，本规格不新增页面。

## 非目标

- 不重写条目文本，不改变条目的负责阶段。
- 不追溯修改已完成计划的证据。

## 验收标准

- AC-SPEC-007（REQ-SPEC-007）：Given 任一条目缺少 result、取值非法，或标记 met 却没有计划 When 运行账本校验 Then 失败并指出条目编号；全部条目齐备且 met 条目有计划时通过。

## 实现完成后更新

- `docs/designs/execution.md`：记录账本新增实施结果字段的当前事实。
