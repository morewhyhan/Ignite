# Ignite 功能规格：规格闭环（spec-closure）

## 背景与目标

模板已有需求、计划、设计、标准、测试和证据，但它们之间只有"需求→验收→测试"这一段被机器强制。标准、设计、ADR 的约束只能以自由文本出现在计划里，改动它们不会触发任何提醒。结果是：文档写得再完整，也无法证明每条规格被执行过。

本规格把《从规格到实现的 DDD 架构闭环》（`docs/standards/specification-to-implementation-ddd.md`）作为模板级目标基线，先把闭环所需的最小事实固定下来：标准被登记、差异被记账、历史被追溯。后续阶段在同一份规格上增量补充编号、绑定、内容门禁与连接性规则。

本阶段交付后，模板能够回答三个问题：这份标准是否是有效来源；本轮差异是否有账可查；已完成的计划能否追溯到它的规格归属。

## 模块边界

- 需求类型：存量修改（模板文档治理与检查器）
- 规格位置：`docs/features/spec-closure.md`
- 计划位置：`docs/plans/20261106-spec-closure-bootstrap.md`（P0）、`docs/plans/20261106-spec-closure-identifiers.md`（P1）
- 检查入口：`scripts/check-docs.mjs`、`scripts/ignite/checks.mjs`、`scripts/ignite/spec-id-registry.mjs`、`tests/contracts/spec-closure.test.ts`、`tests/contracts/spec-closure-ids.test.ts`
- 账本与补录：`docs/others/spec-closure/`
- 决策记录：`docs/others/adr/`

## 业务规则

- R1（REQ-SPEC-001）：`docs/standards/specification-to-implementation-ddd.md` 必须同时出现在标准索引、文档检查必备路径与治理白名单中；缺任一处，文档检查失败并指出缺失位置。
- R2（REQ-SPEC-002）：本轮 52 条差异必须形成机器可读账本，每条包含稳定编号、类别、问题描述、负责阶段与处置；处置只能是实施、保留或延期，延期必须写理由；有对应计划时必须填写真实计划编号。
- R4（REQ-SPEC-004）：`docs/standards/`、`docs/designs/` 与 `docs/others/adr/` 下每份非索引文件都必须携带至少一个稳定编号（STD-区域-NNN、DES-区域-NNN、ADR-四位数字），且全仓唯一。
- R5（REQ-SPEC-005）：计划正文引用的 STD/DES/ADR 编号必须存在于当前注册表；引用未知编号时检查失败并指出该编号。
- R3（REQ-SPEC-003）：五个建设期计划移出工作树后必须有归档补录，包含补录日期、所属发布、集成提交与规格归属；补录只保存可从计划元数据核对的内容，当时的分析过程未记录时必须写明，不得推断。

## 权限、错误与缓存

- 数据归属：不涉及业务数据，仅模板仓库内的文档与检查脚本。
- 未登录、无权与 not-found 的响应：不适用，本规格不暴露运行时接口。
- 非法输入：账本 JSON 不可解析、条目数不为 52、处置值非法、补录缺日期或来源，均视为检查失败。
- Query key 与失效策略：不适用。

## 数据变化与回退

- 既有数据影响：无数据库变化；新增文档与检查规则。
- Migration 与旧数据验证：不涉及 Prisma。
- 回退或前向修复方案：撤销本轮提交即可恢复；新增文件为纯增量，删除后不影响既有检查。
- 破坏性变更授权来源：不适用。

## 原型与交互

- 原型链接：不适用。
- 模块/页面映射：不适用，本规格不新增页面。
- 无外部原型时的设计依据：`docs/standards/specification-to-implementation-ddd.md`。
- 页面状态：不适用。

## 非目标

- 本阶段不引入绑定矩阵字段与 ready 门禁（后续计划负责）。
- 本阶段不改动任何历史计划的正文与证据。
- 本阶段不做文档定稿状态机。

## 验收标准

- AC-SPEC-001（REQ-SPEC-001）：Given 标准索引、文档检查清单或治理白名单缺少该标准文件 When 运行契约测试 Then 失败并指出缺失位置；三处齐备时通过。
- AC-SPEC-002（REQ-SPEC-002）：Given 差异账本缺少任一编号、负责计划或处置，或延期项没有理由 When 运行契约测试 Then 失败；52 条齐备且处置合法时通过。
- AC-SPEC-004（REQ-SPEC-004）：Given 任一标准、设计或 ADR 文件缺少编号，或同一编号出现在两个文件 When 运行注册表扫描 Then 失败并指出文件与编号；全部唯一时通过。
- AC-SPEC-005（REQ-SPEC-005）：Given 计划引用不存在的 STD/DES/ADR 编号 When 运行引用校验 Then 失败并列出未知编号；全部存在时通过。
- AC-SPEC-003（REQ-SPEC-003）：Given 任一条补录缺少补录日期、集成提交、或绑定指向不存在的需求与验收 When 运行契约测试 Then 失败；五个归档计划齐备、绑定可核对、未记录项已写明时通过。
