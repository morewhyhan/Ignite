# GOAL 研究：一杯客人满意的甜牛奶

> 这是示例的研究文件，不是本项目的需求。需求金字塔在 [GOAL.md](./GOAL.md)。
> 研究在前，金字塔在后：先看怎么想出来，再看要什么。

## 一、统一语言

客人，是点这杯、并且为它付钱的人。不付钱的同伴不算，验收以付钱的人为准。

满意，拆成六条：甜度可以接受；温度符合选择；没有结块、没有异味；包装看着漂亮；等待不过长；客人当场没有要求重做。

甜，指白糖、蜂蜜或炼乳，三选一；代糖不算；糖量一到两勺，三勺过甜。

牛奶，指鲜牛奶或全脂奶粉冲兑；植物奶不算。

## 二、场景分析

```
点单：成功订单创建；失败售罄；异常中途改单
取奶：成功拿到合格奶；失败变质或过期；异常换一批
加甜：成功甜度到位；失败超过两勺
混合：成功搅匀；失败结块或分层
调温：成功温度符合；失败温度不对
装杯：成功杯净封平；失败杯脏或渗漏
交付：成功按时；失败超时
品尝：成功客人认可；异常要求重做
```

## 三、事件风暴

```
订单创建、牛奶取出、牛奶倒入杯中、甜味加入、甜度判定完成、混合完成、温度达标、装杯完成、交付完成、客人认可、客人要求重做
```

## 四、命令风暴

```
点单（客人；甜度、温度、数量；售罄不能下单）
取奶（店员；批次；过期不能取）
加甜（店员；糖种、勺数；超过两勺不能加）
搅拌（店员；工具、时长；杯未装好不能搅）
调温（店员；目标温度；未封杯不能交付）
封杯（店员；杯子、封膜；杯口脏不能封）
交付（店员；订单号；超时不能交付）
```

## 五、子域

```
奶源：负责批次与取用，不碰甜度
甜味：负责糖与勺数，不碰温度
混合：负责搅匀，不碰包装
温度：负责档位与达标，不碰交付
外观：负责端上桌状态，不碰封口
包装：负责杯子与封口，不碰内容物
出杯：负责点单、排队、交付时间，不碰制作
```

## 六、识别模型

```
实体：订单、饮品、牛奶批次
值对象：甜度、温度
聚合：订单（根）+ 饮品；牛奶批次
```

## 七、识别上下文

七个边界互不重叠；每个事件恰好属于一个子域。
