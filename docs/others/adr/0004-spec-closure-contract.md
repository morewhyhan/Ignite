# ADR-0004 规格闭环契约

## 状态

已接受（2026-11-06）。

## 背景

模板只有"需求→验收→测试"被机器强制。标准、设计、ADR 的约束只能以自由文本出现在计划里，改动它们不会触发任何提醒。用户要求这些规格被执行清楚、验收清楚，并尽量由代码与检查器承担，而不是依赖执行者的自觉；工具不能阻止宿主任意写入，也不能保证所有模型都遵守。本轮先把可检查的那部分写进检查器。

## 决策

1. 把 `docs/standards/specification-to-implementation-ddd.md` 登记为本轮需求基线，并同时进入标准索引、文档检查清单与治理白名单，禁止"孤儿标准"。
2. 差异以机器可读账本固化：每条有稳定编号、负责计划与处置，延期必须写理由。
3. 历史计划只补录可核对的内容；当时的判断过程未记录时如实标注，不补写。
4. 标准变更时，受影响条目作废并补新；未完成计划必须重新验证，已完成计划只追加"标准后来变更"的记录，不回滚历史结论。

## 替代方案

- 只写文档不做检查：否决，无法阻止下一次遗漏。
- 为 52 条差异各建一个计划：否决，无法独立验收，且制造大量一次性记录。
- 回头重写历史计划的证据：否决，等于伪造证据。

## 代价与复审

代价是每轮准备多写登记与账本；检查器每次改动都要提升检查策略版本，旧证据作废需重跑。若后续引入 `STD-*` 编号，账本的 plan 字段需要重新映射，届时复审本决策。

## 影响

本轮只做 P0；编号、绑定矩阵、内容门禁与连接性由后续计划按同一契约推进。

## 复审记录
