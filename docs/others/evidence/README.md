# 验收证据

`.ignite/runs/` 保存本机运行状态和完整日志，已被 Git 忽略。只有成功运行才会在 `runs/` 发布 schema 2 脱敏清单：Plan、证据 ID、输入与环境指纹、commit、命令结果和日志哈希；这里不保存 PID、绝对路径、日志正文或 secret。

证据只证明它声明的层级，适用层级由 [测试标准](../../standards/testing.md#证据等级) 定义；缺少适用证据时保持未完成，实际状态按 [Plan 规则](../../plans/README.md#完成与证据) 判断。

生成方式：

```text
pnpm ignite check --plan IGT-000 --level auto
pnpm ignite run status
pnpm ignite release status
```

## 运行恢复

长检查先保留 run ID，再用 `pnpm ignite run status` 查心跳、已用时间、命令与退出结果；报告实际进度和未知条件，不因短时间无输出反复启动。

- 相同输入与环境的活动或已通过运行必须复用。失败后先阅读原 run 的状态和日志，区分行为断言、环境、超时、取消、孤儿进程和坏记录。
- 同一失败已重复两次且没有新信息时，停止这条无效路径；改取能区分原因的证据，或说明缺少的条件。不能通过新增重复测试、修改正确断言或机械第三次运行来收口。
- 孤儿运行按已有恢复入口处理；取消自己启动的运行使用 `pnpm ignite run cancel <run-id>`，不任意结束其他任务的进程。损坏记录单独报告，不能伪造成通过。
- 局部排查停止不等于整个 Plan 阻塞；哪些相关工作可独立推进、何时恢复由当前 Plan 的判断负责。

## 有效性与维护

证据与输入、运行环境和 commit 绑定。Plan 完成前，源码、测试、依赖、Schema 或稳定契约等相关输入变化会让旧证据失效；状态与证据回填不要求重复验收相同输入。Plan 完成后，证据按当时 commit 保留为历史事实，新的代码变化必须由新的 Plan 覆盖。Release 状态由 Plan 与有效证据推导，不在 Release JSON 中手填。

发布摘要前核对 runner 的本地运行记录与完整日志；不能手写 receipt 冒充执行。独立 CI 在指定提交执行自己的验收，不把仓库中的清单当成不可伪造证明。日志留在本机，仓库只保存真实脱敏摘要；缺证据、跳过、未执行和过期都如实记录。

模板发布快照不预装建设期运行清单，`runs/` 和 `tdd/` 由首次运行按需创建。模板维护记录保存在 Git 历史；具体产品保留自己产生的运行证据，不能套用模板的绿色结果。
