# 领域推演记录

这份文件记录 GOAL 里的领域是怎么来的：候选、事件、取舍、砍掉的想法。
方法见 [领域怎么拆](../../standards/domain-discovery.md)。

## 候选清单（头脑风暴，不评价）

```
账号  认证  权限  团队  任务  标签  通知  文件  统计  计费  审计  外壳
```

## 事件风暴

```
新用户：打开首页 → 注册 → 进入工作台
老用户：登录 → 恢复会话 → 进入工作台
任何人：登出 → 会话失效 → 回首页
任务：进入任务页 → 新建 → 完成/编辑 → 删除 → 列表更新
越权：打开别人的任务链接 → 提示不存在
```

## 为什么是这两个领域

### 认证领域

- 候选来源：账号、认证、权限、团队
- 事件链：注册 → 登录 → 会话 → 登出
- 为什么合并：账号与认证是同一条事件链，拆开会出现两个领域抢“用户”这个词
- 边界：管身份与会话；不管权限分级、团队成员、找回密码
- 砍掉：邮箱验证、第三方登录、找回密码、多角色权限（当前目标不需要）
- 通用语言：用户 = 有账号的人；会话 = 一次登录的凭证
- 子域类型：支撑子域（必须做，但不构成产品差异）

### 任务领域

- 候选来源：任务、标签、统计
- 事件链：新建 → 编辑 → 完成 → 删除 → 列表
- 为什么独立：任务有自己的实体与生命周期，和身份是两套规则
- 边界：管任务的归属、校验、排序；不管标签、统计、提醒
- 砍掉：标签、子任务、提醒、看板视图（当前不覆盖）
- 通用语言：任务 = 一条待办，有标题、状态、归属
- 子域类型：支撑子域（模板里的示例业务，采用后可替换）

### 外壳（非领域）

- 为什么不算领域：没有自己的业务事件，只做路由、布局与页面组合
- 边界：页面骨架；不含业务规则

## 被砍掉的想法

| 想法          | 为什么砍                                                |
| ------------- | ------------------------------------------------------- |
| 团队 / 多租户 | 当前目标是一个人用一个应用，加进来会把每条 REQ 都变复杂 |
| 通知          | 没有触发源，也没有收件人管理                            |
| 文件上传      | 存储与权限都要额外设计                                  |
| 统计          | 依赖任务数据积累，先把任务做对                          |
| 计费          | 不属于当前产品目标                                      |
| 权限分级      | 只有“自己的/别人的”两种，不需要角色矩阵                 |

## 还没想清楚的

```
1. 注册重复邮箱怎么提示
2. 忘记密码是否要做

```
