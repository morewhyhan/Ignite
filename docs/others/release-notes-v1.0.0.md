# v1.0.0：从「看起来有规则」到「规则真的会拦住人」

## 一句话

这套模板以前只是写了一堆规则；现在这些规则真的会拦住 AI 和人的糊弄，而且验证快到能在一次会话里跑完。

## 先说要解决的问题（主要矛盾）

用这套模板的人会遇到一个具体麻烦：

> AI 写代码很快，但它可以跳过需求、跳过测试、写完就说完成。
> 文档里写着「要有计划、要有证据」，可没人检查，写了等于没写。

也就是说：文档很多，约束为零。

还有一个次要但致命的麻烦：验证一次要 12 分钟，还常跑到一半被系统掐断。
结果是没人愿意跑验证，规则也就永远落不了地。

两个问题合起来，就是这次更新要解决的主要矛盾：

**规则要真的生效，前提是验证要便宜到随手就能跑。**

## 之前是什么样

| 方面 | 之前                             |
| ---- | -------------------------------- |
| 需求 | 可以只写一句话就开工             |
| 计划 | 模板里有字段，缺了没人拦         |
| 测试 | 可以不写测试就实现               |
| 完成 | AI 说完成就是完成                |
| 验证 | 一次 12 分钟，常在跑到一半被中断 |
| 发布 | 没有强制的发布前验证             |
| 文档 | 章节在，内容是空壳               |

## 现在是什么样（有数字）

| 方面 | 现在                                                 |
| ---- | ---------------------------------------------------- |
| 需求 | 每条需求必须挂验收条件，验收条件必须能在测试里被命名 |
| 计划 | 缺字段、缺模块路径、缺审查直接拒绝，连门都进不去     |
| 测试 | 没有真实的失败断言，不许开始实现                     |
| 完成 | 当前检查 + 交付审查 + 设计回写，三样齐了才能标完成   |
| 验证 | 一次 3 分钟，全量测试 2 分 30 秒，发布验证 1 分钟    |
| 发布 | 对同一版本跑构建与验收，不通过不许发                 |
| 文档 | 空章节、空表格、四份说明雷同，检查直接报错           |

## 真正更新了什么（六件事）

1. 红绿灯机制：实现前必须有一条先失败的测试断言，失败信息里带验收编号。
2. 完成门槛：计划标完成要过三道门——当前检查、交付审查、设计回写。
3. 发布验证：对最终版本跑构建与生产态验收，跑不过不算发布。
4. 结构检查：缺章节、留占位、四份说明雷同、草稿进标准目录，全部拦下。
5. 速度：验证从 12 分钟降到 3 分钟，全量测试从 12 分钟降到 2 分 30 秒。
6. 可走通：九步示例，新人照着能从新建计划走到发布验证通过。

## 现在的水平

账本 52 条要求全部落地；测试 307 条通过；
文档检查 75 篇、15 份规格、13 个计划通过；两个发布验证通过。

## 还做不到什么

- 不会自己写业务代码，代码仍由 AI 或人写
- 拦的是没证据、没测试、没回写，拦不了逻辑写得笨
- 还没在真实业务功能上验证过（这次只改文档与检查器）
- 用起来啰嗦：新建一个计划到完成，我们撞了十来类报错

## 怎么验证这套东西真的有用

```bash
export PATH=$HOME/node24/bin:/usr/bin:/bin
cd /home/why/ignite
node scripts/ignite.mjs validate
node scripts/check-docs.mjs
pnpm test
```

三条都通过，说明当前基线是干净的。
想验证它会拦住人：删掉任意一份标准里的状态行，check-docs 会立刻报错。
