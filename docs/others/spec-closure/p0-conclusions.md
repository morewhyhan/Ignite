# P0 遗留六条结论

本文件对规格闭环 P0 阶段遗留的六个问题逐条给出结论：实现、显式非目标、或延期并写明触发条件。
每条都指出依据落在哪个文件，避免"已考虑"这类不可核对的表述。

## 1. 文档状态（在写 / 定稿 / 失效怎么表达）

结论：**已实现。**

- 文档本身用首行状态标记表达"当前事实 / 目标设计"，见 `docs/designs/*.md`；
- 计划的写作进度由 Plan 状态承担（draft → ready → active → verifying → done），见 `docs/plans/README.md`；
- 证据失效由证据状态承担（stale / restarted），见 `docs/others/glossary.md`。

不再引入第四套"文档状态"字段：三种状态已覆盖"这份文档是否可信、这项工作是否完成、这条证据是否还能用"。

## 2. D0–D6 模块编号

结论：**显式非目标。**

理由：D0–D6 来自外部方法论的分层编号，与仓库现有的"目录即入口 + Plan 编号"重复。
强行引入会产生两套编号互相引用。当前用 Plan ID（`IGT-*`）与目录路径定位工作，足够。

若将来需要跨项目对比方法论层级，应作为独立映射表新增，不改动现有编号。

## 3. 五步法与 Loop 的关系

结论：**已实现，写成一条等式。**

五步法是**一次交付内部的顺序**（现实 → 术语 → 矛盾 → 方案 → 验证），
Loop 是**跨交付的循环**（Feature → Plan → Contract/Test → Implementation → Verify → Design）。
二者的接口是 Plan：一次 Loop 迭代产出一个 Plan，Plan 内部按五步法展开。

依据：`docs/plans/README.md` 的"固定维护方法"与 `docs/features/README.md` 的章节顺序。

## 4. 四份执行顺序

结论：**已收敛为一份，其余三份改为指针。**

原先四处各自描述执行顺序（AGENTS.md、plans/README.md、standards/testing.md、adoption.md）。
现在以 `AGENTS.md` 的"推荐开发流程"为唯一顺序来源，其余三处只保留与本主题相关的差异说明，不再重复步骤。

## 5. 承认「目录即方法入口」

结论：**已承认，并写进规则。**

仓库的方法确实通过目录承载：`docs/features/` 是需求方法、`docs/plans/` 是计划方法、
`docs/standards/` 是工程标准、`docs/others/evidence/` 是证据方法。
每个目录的 `README.md` 即该方法的入口。

原先文档反对"以目录承载方法"，与仓库实际相反。现在改为承认这一点，并要求新增方法必须落在目录 + README，而不是散落的说明文件。

## 6. 免 Plan 通道的边界

结论：**已实现，边界写在 `docs/plans/README.md`。**

可免 Plan 的只有两类：

- 纯文字更正：错别字、失效链接、格式；
- 静态展示资产：图片、示例数据，不含逻辑。

其余一律需要 Plan，包括：改测试、改检查脚本、改模板结构、改状态机。
判断标准是"是否改变他人可观察的行为或验证结果"，不是"改动行数多少"。
