# 计划（可选）

> 默认不建计划；需要时它是施工单，交付后归档。需求见 [目标树](../goal/GOAL.md)。

> 默认不建计划。读 `../GOAL.md`，改代码与测试，跑 `pnpm test` 与 `pnpm docs:check`，回写设计，就算完成。

## 什么时候建

```
跨多天的工作
多人协作，需要交接
数据迁移、权限模型、金额计算这类改错代价高的改动
```

## 写四样就够

```
目标：这次要拿到什么可演示的结果
范围：动哪些目录，不动哪些
验收：对应 GOAL 里的哪几条 AC
回退：出问题怎么退回去
```

## 完成与证据

计划完成看两件事：它引用的 AC 在 `../GOAL.md` 里显示已验证，并且真的打开页面点过一遍。
证据怎么留见 [目标树标准](../standards/goal-tree.md#证据怎么记)。

## 模块说明（§8.1）

- 模块目标：需要时把一次改动写成可执行的施工单，交付后归档。
- 输入：GOAL 里的 REQ 与 AC、当前设计事实。
- 输出：一次改动的范围、验收与回退。
- 责任与非责任：只维护施工单；需求在 GOAL，现状在 designs。
- 内部结构：目标、范围、验收、回退。
- 规则与事实源：只引用编号，不复制需求原文。
- 验收标准：引用的 AC 已验证，演示动作跑过。
- 交接：交付后归档，不参与系统描述。

## 发布

默认不做发布记录。需要对外交付时写一条 CHANGELOG，附上本次关闭的 REQ 编号。
