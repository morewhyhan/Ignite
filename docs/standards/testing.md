# 测试标准

> 文档状态：定稿

## 一条测试要回答什么

写测试前先回答三句：

```
它推进哪个用户场景？
通过后用户能感知到什么？
挂了之后，用户在哪个具体场景会出问题？
```

答不出来，就不要写这条测试。

## 每条 AC 至少一条测试

- 测试标题带 `[AC-编号]`，编号必须在 `GOAL.md` 与 Feature 里存在。
- 一个测试只证明一条 AC；多个 AC 共用一条用例时，标题里把编号都写上。
- 测试要调用用户会触发的入口（页面、接口），不测私有函数。

## 层级按真实路径选

| 层       | 用在哪                 |
| -------- | ---------------------- |
| unit     | 纯计算、状态流转       |
| api      | 接口行为、错误码、权限 |
| database | 落库、唯一约束、迁移   |
| browser  | 页面交互、刷新、跳转   |

标错层级会出现“单测全绿、页面不能用”。

## 权限用例必须写

涉及私有资源的 REQ，至少一条 AC 用别人的身份访问：

```
Given 用户 B 已登录，且 A 的资源存在
When B 打开该资源或调用对应接口
Then 页面显示不存在，或请求被拒
```

权限在应用层与查询条件里拦，前端隐藏按钮不算权限。

## 验证说明

每条 AC 的说明写四段，缺一即报错：

```
场景：谁在什么情况下
通过：用户能感知到什么变化
不过：这条挂了，用户在哪个场景出问题
未覆盖：这次没测什么
```

## 证据

```
pnpm goal:status --run
```

跑完把运行日志写进 `docs/others/evidence/goal-runs/`，并把状态写回 `GOAL.md`。
浏览器类 AC 还要存截图：`pnpm goal:status --evidence <AC> <png 路径>`。

## 不做的事

- 不要求红灯回执、覆盖率数字或逐条审查记录。
- 不用占位断言（`expect(true)`、`expect.fail`）凑数。
